# 売上管理機能

実際に売れた **単価（実売単価）** と **売り先（得意先）** を出庫の記録に持たせ、
売上高・売上原価・粗利を一覧・集計できる **売上管理タブ** と **得意先マスタ** を追加した機能です。

これまで出庫の区分に「売上出庫」はありましたが、記録に残るのは数量だけでした。
いくらで売れたのか・誰に売ったのかはどこにも残らず、在庫分析の出庫金額も
`出庫数 × 商品の現在原価` という原価ベースの概算しか出せませんでした。
そのため「今月いくら売れたか」「どの商品・どの得意先が儲かっているか」が分かりませんでした。

売上専用のテーブルは作っていません。ロット追跡・廃棄ロス・原価履歴と同じく
**帳票（入出庫帳票）を読んで組み立てる** 方式で、
`migrations/0010_sales.sql` は得意先マスタの新設と既存テーブルへの `ALTER TABLE` だけです。

## データモデル

```ts
// 得意先 (販売先) マスタ。仕入先マスタと対になる
interface Customer {
  id: string;
  name: string;    // 得意先名 (必須・重複不可)
  code: string;    // 得意先コード (任意・重複不可)
  contact: string; // 担当者名
  phone: string;
  email: string;
  address: string;
  note: string;
  active: boolean; // 取引中か (false = 取引停止)
}

interface StockTransaction {
  // ...既存のフィールド
  unitPrice?: number;     // 区分で意味が変わる: 入荷=仕入単価 / 廃棄=ロットの原価 / 売上出庫=実売単価
  customerId?: string;    // 得意先マスタの id。「売上出庫」だけが持つ
  costUnitPrice?: number; // 出庫した時点のロット原価。「売上出庫」だけが持つ
}
```

押さえておきたいのは次の3点です。

1. **売上は「売上出庫」の帳票そのもの。** 売上を登録すると FEFO 出庫が走り、区分「売上出庫」の
   記録が引き当てたロットの数だけ残る。売上管理タブはその記録を読み直しているだけで、
   別の場所に売上データを持たない（調整出庫・廃棄・移動は売上に数えない）。
2. **原価は出庫したその場で写し取る。** 売れたロットは在庫から減るため、あとから
   「そのとき何円のロットを出したか」を引き直すことはできない。だから `costUnitPrice` に
   `lotUnitCost(lot, product)` の値をコピーしておき、粗利（売上金額 − 原価）を
   いつでも再計算できるようにしている（一括廃棄が廃棄時の原価を残しているのと同じ理由）。
3. **得意先は id 参照。** カテゴリ・倉庫・仕入先と同じで、改名しても過去の売上の紐づけは切れず、
   画面の表示だけが一斉に変わる。

### 単価が入っていない売上（概算）

この機能より前に記録された売上出庫や、単価を入力しないまま出庫した記録には
`unitPrice` / `costUnitPrice` がありません。その行は

- 実売単価 → **商品の販売定価**（`Product.price`）
- 原価 → **商品の現在原価**（`Product.costPrice`）

で代用し、画面・CSV に「概算」と印をつけます（廃棄ロスが古い記録で現在原価にフォールバックするのと同じ扱い）。
商品ごと削除されている場合は 0 円として扱います。

**販売単価 0 は「0円で売った」ではなく「未入力」** です（入荷予定の仕入単価と同じ約束）。
0 のときは帳票に単価を書かず、集計では販売定価で概算します。

## 画面: 売上管理タブ

`SalesView.tsx`。タブの並びは 入荷予定 の次（入荷と売上を隣り合わせにしています）。

- 上部に 売上高 / 売上原価 / 粗利 / 粗利率 のサマリカード（絞り込み後の範囲で集計）
- キーワード（商品名・SKU・得意先名）／期間／得意先（「得意先なし」だけの絞り込みも可）／倉庫で絞り込み
- **明細 / 商品別 / 得意先別 / 日別** の4つの切り口を1画面で切り替え
  - 明細：日時・商品名・SKU・ロットNo・倉庫・得意先・数量・売上単価・売上金額・原価・粗利・粗利率
  - 集計：件数・数量・売上金額・原価・粗利・粗利率・構成比（商品別・得意先別は売上高の多い順、
    日別だけは新しい日付順）
- CSV は明細（`CSV_EXPORTS.sales`）と集計（`CSV_EXPORTS.salesSummary`）で出し分ける

### 売上の登録

「+ 売上を登録」（`SalesEntryModal.tsx`）から、商品・数量・販売単価・得意先・出庫元倉庫・備考を入力します。

- 販売単価の初期値は **その商品の販売定価**。値引きしたらここを書き換える（書き換えた値が売上になる）
- 引当プレビューは FEFO出庫 とまったく同じ `planFefoShipment` の結果で、ロットごとの原価も出す
- 売上金額・原価・粗利をその場でプレビューし、在庫が足りないときは登録ボタンを押せない
- 登録すると `recordSale` → `shipFefo`（区分は 売上出庫 固定）で在庫が減り、
  引き当てたロットの数だけ帳票に記録される（備考は既定で `売上登録`）

在庫一覧からの出庫でも同じ内容を記録できます。

- **FEFO出庫モーダル**（`ShipFefoModal.tsx`）: 出庫区分が「売上出庫」のときだけ販売単価・得意先の
  入力欄と粗利プレビューが出る
- **ロット行の「出庫」**（`App.tsx` の `StockIoModal`）: 同じく「売上出庫」を選んだときだけ入力欄が出る

## 画面: 得意先マスタ

`CustomerMasterView.tsx` / `CustomerModal.tsx`。商品マスタタブの最後のセクション（仕入先マスタの下）。
仕入先マスタと同じ構成で、項目が多いのでインライン編集ではなくモーダルで編集します。

- 一覧は 取引中が先 → 得意先名順。キーワード（名前・コード・担当者・電話・メール）で絞り込み
- 得意先ごとの売上件数・売上数量・売上金額・粗利・最終売上日を表示（帳票から集計）
- **売上の記録がある得意先は削除できません。** 取引が終わったら「取引停止」にすると、
  過去の売上を残したまま売上登録の選択肢から外れます（`selectableCustomers`）

## 実装

| 関数 | 役割 |
|------|------|
| `salesRows(ledger, products, customers)` | 帳票の「売上出庫」を新しい順の売上明細へ整形（単価・原価が無い行は概算にフォールバック） |
| `filterSales(rows, filter)` | キーワード／得意先（`NO_CUSTOMER` = 得意先なし）／倉庫／期間で絞り込み |
| `salesTotals(rows)` | 件数・数量・売上高・原価・粗利・粗利率・平均単価 |
| `salesProductSummaries` / `salesCustomerSummaries` / `salesDailySummaries` | 商品別／得意先別／日別の集計（共通の `SalesSummary` 型） |
| `salesCsv` / `salesSummaryCsv` | CSV（`売上明細_YYYY-MM-DD.csv` / `売上集計_YYYY-MM-DD.csv`） |
| `customerValidationError` / `normalizeCustomerInput` | 得意先の入力チェック（画面と `addCustomer`/`updateCustomer` が共有） |
| `customerUsage(rows)` / `customerRows(customers, rows, ...)` | 得意先ごとの売上実績と、マスタ一覧の組み立て |
| `customerCsv` / `exportCustomerCsv` | CSV（`得意先一覧_YYYY-MM-DD.csv`） |
| `recordSale(input)` | 売上登録。`shipFefo` に区分「売上出庫」と実売単価・得意先を渡す薄いラッパー |
| `addCustomer` / `updateCustomer` / `deleteCustomer` | 得意先マスタの編集（在庫は動かないので帳票には記録しない） |

`planFefoShipment` の引当結果にも原価が乗ります（`FefoAllocation.unitCost` と `FefoPlan.cost`）。
プレビューと実際の出庫が同じ関数を共有しているので、画面に出た粗利と記録される粗利がずれません。

在庫分析の「出庫金額」は従来どおり `期間出庫数 × 商品の現在原価`（原価ベースの概算）のままです。
売上高・粗利を見るのは売上管理タブの役割、という住み分けにしています。

テストは純粋関数と `recordSale` が `src/test/sales.test.ts`、得意先マスタが `src/test/customer.test.ts`、
画面が `src/test/SalesView.test.tsx` / `src/test/CustomerMasterView.test.tsx` です。
