# 発注履歴タブ

**発注書として印刷した内容**を確認するための**見るだけの画面**です。仕入先マスタの「発注書」から
印刷するたびに、そのとき印刷した明細がここに記録として積み上がっていきます。

「あの発注書、印刷したはずだけど内容を確認したい」「もう一度同じものを印刷したい」というときに使う画面で、
ここから新しく発注を作ったり、内容を書き換えたりすることはできません。

この画面で在庫が動くことはありません。何を押しても記録は増えません（「再表示」からの印刷も同様です）。

---

## 1. 画面の構成

```
[仕入先名・商品名・SKUで検索...] [開始日 〜 終了日] [仕入先▼] [条件クリア]
─────────────────────────────────────────────────────
2件                              [CSVエクスポート（発注履歴）]
─────────────────────────────────────────────────────
印刷日時         発注日      仕入先       件数  数量  金額     操作
2026/09/12 16:37 2026-09-12  山田乳業      1    24   ¥2,880   [再表示]
2026/09/10 10:15 2026-09-10  朝日ベーカリー 2    32   ¥3,120   [再表示]
```

一覧は**印刷した日時の新しい順**に並び、**1回の「印刷」操作 = 1行**です（複数の明細を一度に
印刷しても、まとめて1行になります）。

### 絞り込み

| 条件 | 対象 |
|------|------|
| キーワード | 仕入先名、または含まれる明細のいずれかの商品名・SKU の部分一致 |
| 期間 | 印刷日時（開始日・終了日とも、その日を含む） |
| 仕入先 | 仕入先マスタに登録された仕入先 |

---

## 2. 再表示・再印刷

行の「再表示」を押すと、**印刷したときと同じ内容**の発注書が開きます。

- 宛先（仕入先名・住所・連絡先）、発注元（自社名・住所・連絡先）、発注日、明細（商品名・SKU・
  入荷予定日・数量・単価・金額）は、すべて**印刷した時点の記録**です。あとで仕入先マスタの
  住所を直したり、商品名を改名したりしても、**この画面の表示は変わりません**（入出庫帳票の
  過去の記録と同じ考え方です）
- チェックボックスによる明細の選択や「明細を追加」はありません（履歴は確定した記録なので、
  変更する必要がないためです）
- 「印刷」を押すと同じ内容をもう一度印刷できます。これは**新しい発注ではない**ので、発注履歴も
  入荷予定も増減しません

---

## 3. どの記録が並ぶか

仕入先マスタの「発注書」画面で**「印刷」ボタンを押したとき**の内容だけが並びます。

- 発注書のプレビューを開いただけ（印刷ボタンを押していない）では記録されません
- 明細のチェックを外して印刷した場合、**その回に印刷しなかった明細は記録されません**
- 一件も記録がない場合は、案内文だけが表示されます

## 4. CSVエクスポート

「CSVエクスポート（発注履歴）」で、**絞り込み後の一覧を明細1行ごと**に
`発注履歴_YYYY-MM-DD.csv` へ出力します（一覧画面の「1回の印刷 = 1行」とは違い、CSVは明細単位です）。

```
印刷日時,発注日,仕入先,商品名,SKU,入荷予定日,数量,単価,金額
2026/09/12 16:37,2026-09-12,山田乳業,牛乳,ML-001,2026-09-14,24,120,2880
```

---

## 5. 注意点

- **商品名・仕入先の情報は印刷した時点のスナップショットです。** 現在の商品マスタ・仕入先マスタの
  最新の内容とは一致しないことがあります（改名・削除していても、この画面の表示は変わりません）
- 発注書自体の作成・印刷・明細の選択については [master.md](master.md) の「発注書」を参照してください
- **誰が操作したかは記録されません**（ログイン機能がないため）
- ヘッダーの「リセット」を押すと発注履歴もすべて消えます

### 開発者向けメモ

- 画面：`src/PurchaseOrderHistoryView.tsx`（絞り込み条件だけがローカル状態）＋
  再表示・再印刷の読み取り専用モーダル `src/PurchaseOrderReprintModal.tsx`
- 計算：`src/useInventory.ts` の `purchaseOrderPrintGroups` / `purchaseOrderHistoryCsv` /
  `exportPurchaseOrderHistoryCsv`
- 専用の永続データを持つ（`purchase_order_prints` テーブル、`migrations/0009_purchase_order_prints.sql`）。
  1回の印刷操作につき、印刷した明細の数だけ行を作る（`入出庫帳票`と同じ「1件1行」の方針）
- 記録を作るのは `printPurchaseOrder`（発注書モーダルの「印刷」から呼ばれる）。同時に対象の
  入荷予定へ `printedAt` も記録する（二重発注の防止。[master.md](master.md) の「発注書」参照）
- 詳しい設計は [../purchase-order-history-feature.md](../purchase-order-history-feature.md)
