# データの持ち方と共通ルール

画面ごとの説明では書ききれない、**システム全体を貫くルール**をまとめています。
仕様の疑問（「この数字は何を足しているのか」「この操作をすると何が残るのか」）はここを見てください。

---

## 1. データの構造

保存されているデータは7種類です。

```
カテゴリ ──< 商品 ──< ロット >── 倉庫
   (分類)     (品目)    (在庫の実体)   (置き場所)
              │                          │
              └──< 入荷予定 >────────────┘
                   (入荷待ち。在庫ではない)
                        │
                     仕入先 (発注先)

                 入出庫帳票（在庫が動いた記録。上とは独立して積み上がる）
```

| データ | 持っている情報 | 補足 |
|--------|----------------|------|
| **カテゴリ** | 名前 | 商品の分類 |
| **商品** | 商品名、SKU、JANコード、カテゴリ、最低在庫数（発注点）、販売定価、原価 | **在庫数は持ちません** |
| **ロット** | ロットNo、賞味期限、**在庫数**、倉庫、原価（任意） | 必ずどれか1つの商品に属します。原価を入力しなければ商品の原価を使います |
| **倉庫** | 名前、色 | |
| **仕入先** | 仕入先名、コード、担当者、電話、メール、住所、標準リードタイム、取引状態、備考 | 発注先。入荷予定から参照されます |
| **入荷予定** | 商品、入荷予定日、予定数量、入荷済数量、入荷先倉庫、ロットNo、賞味期限、仕入先、仕入単価、備考 | **在庫数には数えません**。入荷するとロットになります |
| **入出庫帳票** | 日時、区分、商品名・SKU、ロットNo、数量、移動元／移動先倉庫、備考 | 記録した時点の値を写し取って保持 |

### 押さえておきたい3点

1. **在庫数はロットにしかありません。** 商品の「合計在庫」は、その商品のロットの在庫数を足したものです。
2. **商品はカテゴリを、ロットは倉庫を、入荷予定は仕入先を「名前」ではなく内部の番号で参照しています。**
   だからカテゴリ名・倉庫名・仕入先名を変更しても、紐づけは切れずに全画面の表示だけが変わります。
3. **帳票は商品名・SKUを文字としてコピーして持ちます。**
   だから商品を改名・削除しても、過去の帳票の記録はそのまま読めます（当時の名前で残ります）。
4. **入荷予定は在庫と別物です。** 合計在庫・在庫金額・ダッシュボードのどの数字にも入りません。
   「入荷」して初めてロットになり、在庫として数えられます。

## 2. 在庫が動く操作と帳票の対応

**在庫数が変わる操作は、必ず帳票に記録されます。**逆に言えば、帳票に無い在庫の変化はありません。

| 操作した場所 | 操作 | 記録される区分 | 備考欄 | 記録される件数 |
|--------------|------|----------------|--------|----------------|
| 在庫一覧 | + ロット追加（在庫数1以上） | 入荷 | `ロット追加` | 1件 |
| 在庫一覧 | + ロット追加（在庫数0） | — | — | 記録なし |
| 在庫一覧 | ロット行の「入庫」 | 選んだ区分（入荷 / 調整入庫） | 空欄 | 1件 |
| 在庫一覧 | ロット行の「出庫」 | 選んだ区分（売上出庫 / 調整出庫 / 廃棄） | 空欄 | 1件 |
| 在庫一覧 | ロット行の「移動」 | 移動 | `倉庫移動` | 1件 |
| 在庫一覧 | ロット編集で倉庫を変更 | 移動 | `ロット編集` | 1件 |
| 在庫一覧 | ロット編集で数量を変更 | 調整入庫 / 調整出庫 | `ロット編集` | 1件 |
| 在庫一覧 | ロット編集で倉庫と数量を両方変更 | 移動 ＋ 調整入庫/調整出庫 | `ロット編集` | 2件 |
| 在庫一覧 | ロット削除（在庫が残っている） | 調整出庫 | `ロット削除` | 1件 |
| 在庫一覧 / 商品マスタ | 商品削除 | 調整出庫 | `商品削除` | 在庫の残っているロットの数だけ |
| 在庫一覧 | FEFO出庫 | 選んだ区分（売上出庫 / 調整出庫 / 廃棄） | `FEFO出庫` | 引き当てたロットの数だけ |
| ダッシュボード | 選択したロットを廃棄 | 廃棄 | `一括廃棄` | 廃棄したロットの数だけ |
| 入荷予定 | 行の「入荷」 | 入荷 | 入力した備考、空欄なら `入荷予定（仕入先名）` | 1件（仕入単価・仕入先も一緒に記録） |
| ヘッダー | Excelインポート | 調整入庫 / 調整出庫 | `Excelインポート` | 数量が変わったロットの数だけ |
| 棚卸 | 棚卸を確定 | 調整入庫 / 調整出庫 | `棚卸` | 差異のあるロットの数だけ |

**帳票に記録されない操作**（在庫数が変わらないため）

- 商品の追加・編集（商品名、SKU、価格、発注点、カテゴリの変更）
- カテゴリ・倉庫・仕入先の追加・編集・削除（取引停止・再開を含む）
- 入荷予定の追加・編集・取消・削除（在庫が動くのは「入荷」したときだけ）
- 各画面の検索・絞り込み・並べ替え・CSVエクスポート
- ロット追跡（帳票を読んで並べ替えるだけの画面で、在庫も帳票も変えません）
- ヘッダーの「リセット」（帳票ごと消えるため記録も残りません）

**帳票を読んで作られるもの**（帳票が唯一の情報源になっているもの）

| 画面 | 何を作るか | もとにする記録 |
|------|------------|----------------|
| ダッシュボード | 廃棄ロスの商品別集計 | 区分が「廃棄」の記録 |
| ロット追跡 | 1ロットの入荷→移動→出庫の時系列、既に出た数量の内訳 | そのロット（商品＋ロットNo）の全記録 |
| 原価履歴 | 仕入単価の推移（前回比つき） | 区分が「入荷」かつ仕入単価が入っている記録 |

そのため、**帳票を記録し始める前からある在庫は追跡できません**（記録がないため）。
ロット追跡ではその場合に「入出庫の記録がありません」「帳票上の残数と現在庫が一致しません」と注意書きを出します。

## 3. 数字の定義

同じような名前の数字が複数あるので、計算のもとを明記します。

| 用語 | 計算 | 使われている場所 |
|------|------|------------------|
| 合計在庫 | その商品のロットの在庫数の合計 | 在庫一覧、要発注の判定 |
| 在庫総額 | 全ロットの `在庫数 × 販売定価` | 共通サマリカード |
| 在庫金額（原価） | 全ロットの `在庫数 × 原価`。**原価はロットごとの原価**（未入力のロットは商品の現在原価） | ダッシュボード、倉庫別・カテゴリ別集計 |
| 要発注（在庫不足） | `合計在庫 ≦ 最低在庫数` の商品 | アラートバナー、ダッシュボード |
| 欠品 | 合計在庫が0の商品（要発注の内数） | ダッシュボード |
| 不足数 | `最低在庫数 − 合計在庫`（マイナスにはならない） | 要発注リスト |
| 発注見込金額 | `不足数 × 原価`。まだ手元にない（＝ロットがまだない）在庫の見込みなので、常に**商品の現在原価**を使う | 要発注リスト |
| 残数（入荷予定） | `予定数量 − 入荷済数量`（キャンセル時は0） | 入荷予定 |
| 遅延（入荷予定） | 入荷予定日 < 今日 かつ 残数 > 0 | 入荷予定 |
| 差異（棚卸） | `実数 − 帳簿在庫` | 棚卸 |
| 差異金額（棚卸） | `差異 × 原価`。**原価はそのロットの原価**（未入力なら商品の現在原価） | 棚卸 |
| 廃棄ロス金額 | 区分が「廃棄」の記録の `数量 × 原価`。廃棄した時点のロットの原価が記録として残るのでそれを使う（未入力のロット・古い記録は**現在の**商品原価を使う概算） | ダッシュボード |
| 構成比 | その倉庫／カテゴリの在庫金額（原価） ÷ 全体の在庫金額（原価） | ダッシュボード |
| 残日数 | 賞味期限 − 今日（**0＝今日が期限日**、マイナス＝期限切れ） | 期限バッジ、期限アラート |
| 帳票上の残数（ロット追跡） | そのロットの `入庫の合計 − 出庫の合計`（移動は増減しない） | ロット追跡 |
| 現在庫（ロット追跡） | そのロットNoのロットの在庫数の合計（在庫0のロットは除く） | ロット追跡 |

### 期限の状態

| 状態 | 条件 |
|------|------|
| 期限切れ | 残日数 < 0 |
| 期限間近 | 残日数 0〜7日（ダッシュボードのみ 7 / 14 / 30日に切替可）。うち残日数0は「今日まで」と表示 |
| 通常 | それ以降、または賞味期限なし |

**在庫0のロットの扱いは画面によって違います。**

| 画面 | 在庫0のロット |
|------|---------------|
| 画面上部の共通アラート・サマリカード | **数える** |
| ダッシュボードの期限切れ／期限間近／期限アラート | 数えない |
| FEFO出庫の引当 | 対象外 |

在庫0のロットを残しておくと上部のアラートが消えないため、使い切ったロットは削除する運用を推奨します。
（ダッシュボードの「選択したロットを廃棄」は、この理由から**廃棄したロットを在庫0で残さず取り除きます**。）

## 4. 入力チェック一覧

| 入力欄 | ルール | 違反したとき |
|--------|--------|--------------|
| 商品名 | 必須 | 保存できない（商品マスタでは「商品名とSKUは必須です」） |
| SKU | 必須。**重複チェックはなし** | 同上 |
| JANコード | 任意。数字8桁または13桁 | 「JANコードは数字8桁または13桁で入力してください」 |
| カテゴリ | 必須（選択式） | 保存できない |
| 最低在庫数 / 販売定価 / 原価 | 0以上の数値。空欄は0扱い | — |
| ロットNo | 必須。**半角数字8桁**。数字以外は入力できない | 「半角数字8桁で入力してください」 |
| 賞味期限 | 任意（日付選択）。入力するとロットNoを自動生成 | — |
| ロットの在庫数 | 0以上 | — |
| ロットの原価 | 任意。0以上の数値。既定値は商品の現在の原価。既定値のまま保存すれば商品原価に追従し続け、値を変えると以後そのロット専用の原価として固定される | — |
| 出庫数量（ロット行） | 1以上、そのロットの在庫数以下 | ボタンが押せない |
| 移動数量 | 1以上、そのロットの在庫数以下 | ボタンが押せない |
| FEFO出庫数量 | 1以上、引当可能な在庫の範囲内 | 不足メッセージが出てボタンが押せない |
| 入荷予定の予定数量 | 1以上 | 保存ボタンが押せない |
| 入荷予定のロットNo | 必須。**半角数字8桁**。数字以外は入力できない | 「半角数字8桁で入力してください」 |
| 入荷数量 | 1以上、その予定の**残数以下** | ボタンが押せない |
| 入荷予定の仕入単価 | 任意。0以上の数値。空欄は0（未入力）扱い | — |
| 棚卸の実数 | 0以上の整数。空欄＝未カウント | 0以上の整数に丸められる |
| カテゴリ名 | 必須。既存と同名は不可 | 何も起きない（メッセージは出ません） |
| 倉庫名 | 必須（前後の空白は自動削除） | 追加されない |

**削除の制約**

| 対象 | 削除できる条件 |
|------|----------------|
| 商品 | いつでも（在庫があれば調整出庫として帳票に残る。**その商品の入荷予定も一緒に消えます**） |
| ロット | いつでも（在庫があれば調整出庫として帳票に残る）。ダッシュボードで廃棄した場合は廃棄として残る |
| カテゴリ | そのカテゴリの商品が0件のときだけ |
| 倉庫 | その倉庫のロットが0件、**かつ入荷待ちの入荷予定が0件**のときだけ |
| 入荷予定 | いつでも（入荷済みの在庫・帳票は残る。履歴を残したいときは「取消」を使う） |

## 5. データの保存タイミング

- 画面での変更は、その操作をした時点で自動的にサーバーへ保存されます（保存ボタンを押す必要はありません）。
- 保存は種類ごと（商品＋ロット / 倉庫 / カテゴリ / 帳票 / 入荷予定）に、**その種類の全データを送り直す**方式です。
  そのため**複数人が同時に編集すると、あとから操作した人の内容で上書きされます。**同時編集は想定していません。
- 画面を開いたときにサーバーの内容を読み込み、それを正として表示します。
- サーバーにつながらない場合もアプリは動作しますが、変更は保存されません（画面を閉じると失われます）。
- 棚卸の「実数」だけは例外で、**確定するまで保存されません**（画面を再読み込みすると消えます）。

## 6. 既知の注意点

- **残日数の計算は世界標準時（UTC）の日付を基準にしています。** 日本時間の午前9時より前は、
  日付の切り替わりが1日ずれて「残日数が1日多く」表示される場合があります。
- **ロットNoは重複し得ます。** 賞味期限から自動生成するため、同じ期限のロットを分けて登録したり、
  ロットを部分移動したりすると同じロットNoが並びます。Excelインポートは SKU＋ロットNo で1件だけを探すため、
  重複していると先に見つかった1件だけが更新されます。
- **SKUの重複チェックはありません。** 同じSKUの商品を2つ作れてしまうため、運用側で一意にしてください。
- **取り消し（アンドゥ）はありません。** 削除・棚卸の確定・リセットは元に戻せません。
- **操作した人は記録されません。**

### 開発者向けメモ

- 型定義・状態・全ミューテーション・集計関数：`src/useInventory.ts` に集約（`src/types.ts` は使われていない旧ファイル）
- 保存：`GET /api/state` で全件取得、変更のたびに `PUT /api/{products,warehouses,categories,ledger,inbound-plans}` で全置換（`worker/index.ts` → D1）
- 旧データの移行：`migrateProducts`（倉庫未設定→販売倉庫、旧カテゴリ文字列→カテゴリマスタ）、`migrateLedger`（旧「入庫／出庫」区分の変換）
- 新しい在庫変更処理を追加するときは、必ず `addTransaction` / `addTransactions` で帳票に記録すること
