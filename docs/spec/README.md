# 食品在庫管理システム 仕様説明書

このフォルダは、**プログラムが読めない方でも「この画面で何ができて、どう動くのか」が分かる**ことを目的とした
画面・機能単位の仕様書です。開発者向けの補足（どのファイルに書かれているか）は各ページの末尾に小さくまとめています。

---

## 1. このシステムは何をするものか

食品を扱う事業者向けの **在庫管理システム**です。ブラウザだけで使えます。

普通の在庫管理と大きく違うのは、**商品の在庫を「1つの数字」で持たない**点です。
同じ「牛乳」でも、賞味期限が違えば別物として数えます。この「同じ商品の、同じ期限・同じ置き場所のかたまり」を
**ロット**と呼び、在庫はすべてロット単位で記録します。

```
商品：牛乳（SKU: ML-001）
 ├ ロット 20260703（賞味期限 7/3、販売倉庫）… 10個
 └ ロット 20260707（賞味期限 7/7、販売倉庫）… 10個
                                     合計在庫 20個
```

こうしておくことで、

- 入荷予定から **予定どおりのロットをそのまま作れる**（ロットNo・賞味期限の入力し直しが不要）
- 期限が近い在庫・切れた在庫を **ロット単位で警告**できる
- 出庫のとき **期限の近いものから自動で引き当てる**（FEFO出庫）ことができる
- 「どのロットを、いつ、どこから、いくつ動かしたか」が **帳票にすべて残る**
- 回収が起きたとき、**そのロットが入ってから出るまでを1画面で追える**（ロット追跡）

という、食品在庫で必要になる管理ができます。

## 2. 画面の全体像

画面はすべて1ページの中でタブを切り替えて使います。ログインや権限の区別はありません（誰が開いても同じ画面です）。

| タブ | 何をする画面か | 詳細 |
|------|----------------|------|
| ダッシュボード | 在庫全体の状況と「いま手を打つべきもの」を見る。期限切れの一括廃棄もできる | [dashboard.md](dashboard.md) |
| 在庫一覧 | 日々の入庫・出庫・移動を行う。**メインの作業画面** | [inventory.md](inventory.md) |
| 入荷予定 | 発注済み・入荷待ちを登録し、届いたら在庫にする | [inbound.md](inbound.md) |
| 商品マスタ | 商品・カテゴリ・倉庫・仕入先の登録内容を整える | [master.md](master.md) |
| 棚卸 | 実地棚卸で数えた数を入力し、帳簿の在庫を合わせる | [stocktake.md](stocktake.md) |
| 入出庫帳票 | 過去の在庫の動きを検索・確認する | [ledger.md](ledger.md) |
| ロット追跡 | 1つのロットが入ってから出るまでを時系列で追う（回収対応） | [trace.md](trace.md) |
| 原価履歴 | 仕入単価の推移を確認する（見るだけ） | [cost-history.md](cost-history.md) |
| 発注履歴 | 発注書として印刷した明細の記録を確認し、同じ内容を再表示・再印刷する（見るだけ） | [purchase-order-history.md](purchase-order-history.md) |
| 在庫分析 | 出庫実績からABCランク・在庫回転率・滞留在庫を見る。発注点の見直しもできる | [stock-analysis.md](stock-analysis.md) |

このほか、全タブに共通する画面上部（アラート・サマリ・エクスポートボタンなど）は
[common.md](common.md) にまとめています。

データの持ち方（商品・ロット・倉庫・カテゴリ・仕入先・帳票の関係）と、
「どの操作をすると帳票に何が記録されるか」の一覧は [data-and-rules.md](data-and-rules.md) にあります。

```
        ┌──────────────────────────────────────────┐
        │ ヘッダー（リセット / CSV / Excel 入出力） │  ← 全タブ共通
        ├──────────────────────────────────────────┤
        │ アラートバナー・サマリカード             │  ← ダッシュボード・在庫分析以外
        ├──────────────────────────────────────────┤
        │ [ダッシュボード][在庫一覧][入荷予定]     │
        │ [商品マスタ][棚卸][入出庫帳票]           │
        │ [ロット追跡][原価履歴][発注履歴]         │
        │ [在庫分析]                               │
        ├──────────────────────────────────────────┤
        │                                          │
        │           選んだタブの中身               │
        │                                          │
        └──────────────────────────────────────────┘
```

## 3. 用語集

社内で言葉がぶれやすいところなので、このシステムでの意味を定義します。

| 用語 | このシステムでの意味 |
|------|----------------------|
| **商品** | 「牛乳」「食パン」といった品目。商品自体は在庫数を持たず、ロットの合計が在庫数になります |
| **SKU** | 商品を一意に識別する社内コード（例: `ML-001`）。Excelインポートの突き合わせキーになります |
| **JANコード** | 市販品のバーコード番号（8桁または13桁）。自社ラベル品など無い商品は未設定で構いません |
| **ロット** | 同じ商品の中で「賞味期限」と「保管倉庫」が同じ在庫のかたまり。在庫数はここに付きます |
| **ロットNo** | ロットの識別番号。半角数字8桁。賞味期限を入れると `20260703` のように自動生成されます |
| **倉庫** | 在庫の置き場所（販売倉庫・保留倉庫・不良倉庫など）。色つきバッジで区別します |
| **カテゴリ** | 商品の分類（乳製品・パンなど）。集計と絞り込みに使います |
| **仕入先** | 発注先。入荷予定で選びます。商品マスタタブの仕入先マスタで登録します |
| **標準リードタイム** | 仕入先ごとの「発注してから届くまでの日数」。入荷予定日の初期値に使われます |
| **仕入単価** | 入荷予定に入力する仕入れ値（円）。入荷すると入出庫帳票にコピーされ、原価履歴タブに並びます |
| **原価履歴** | 仕入単価の推移を商品×仕入先ごとに確認できる画面（原価履歴タブ）。過去の記録を見るだけで、商品の「原価」そのものは変わりません |
| **取引停止（仕入先）** | 取引が終わった仕入先の状態。一覧には残りますが、新しい入荷予定では選べなくなります |
| **発注書** | 仕入先マスタから作る、その仕入先への注文書。ブラウザの印刷機能でそのまま印刷・PDF保存できます |
| **発注履歴** | 発注書として印刷した内容の記録（発注履歴タブ）。あとから同じ内容を再表示・再印刷できます。過去の記録を見るだけで、印刷しても在庫や入荷予定は変わりません |
| **発注点（最低在庫数）** | 商品ごとに決める「これを下回ったら発注する」ライン。**合計在庫がこの数以下**になると要発注として警告します |
| **ABC分析** | 出庫金額の大きい順に商品を並べ、上位70%をA・90%までをB・残りをCに分ける分類（在庫分析タブ）。どの商品に手をかけるべきかの優先順位付けに使います |
| **在庫回転率** | 集計期間の出庫数 ÷ いまの在庫数。大きいほどよく回っている在庫です |
| **在庫日数** | いまの在庫数 ÷ 1日あたりの出庫数。今のペースで在庫が何日分あるか |
| **滞留在庫** | 在庫が残っているのに一定期間（30/60/90日）出庫のない在庫。値引き・処分の検討対象です |
| **安全在庫日数** | 発注点の見直し提案で、リードタイムに上乗せする余裕の日数（3/7/14日） |
| **入荷予定** | 発注済みでまだ届いていない在庫の予定。**それ自体は在庫ではありません**（入荷して初めて在庫になります） |
| **残数（入荷予定）** | 予定数量 − 入荷済数量。まだ届いていない数量です |
| **帳簿在庫** | システムが持っている在庫数。棚卸で「実数」と比べる対象です |
| **実数** | 実地棚卸で人が数えた実際の在庫数 |
| **入出庫帳票** | 在庫が動いた記録の一覧。すべての在庫変動が1件ずつ残ります |
| **トレーサビリティ（ロット追跡）** | 1つのロットが「いつ入って、どこを経由して、いつ出たか」を追えること。回収（リコール）のときに必要になります |
| **FEFO** | First Expired, First Out＝「先に期限が来るものから先に出す」という出庫の考え方 |
| **廃棄** | 期限切れなどで在庫を処分すること。出庫の区分のひとつで、売上にならない在庫の減り方です |
| **廃棄ロス金額** | 廃棄した数量 × 原価。捨てたことで失った金額 |
| **期限切れ** | 賞味期限が今日より前のロット |
| **期限間近** | 賞味期限まで **0〜7日**のロット（ダッシュボードだけ7/14/30日に切り替え可） |

## 4. データの保存について

- 入力した内容は、画面を操作した時点で **サーバー（クラウド上のデータベース）に自動保存**されます。
  「保存ボタンを押し忘れて消えた」ということは起きません（各画面の保存ボタンは、その場の編集を確定するものです）。
- 保存は自動・即時で、**取り消し（アンドゥ）機能はありません**。削除の確認ダイアログが出たときは内容をよく確認してください。
- サーバーにつながらない状態でもアプリは動きますが、その間の変更は保存されません（画面を閉じると消えます）。
- ヘッダーの **リセット**を押すと、在庫も帳票もすべて破棄してサンプルデータの状態に戻ります。運用中は使わないでください。

## 5. このシステムに「無い」もの

期待の行き違いを防ぐため、意図的に持っていない機能を明記します。

- ログイン・ユーザー管理・権限（誰の操作かは記録されません）
- 発注書のメール送信・FAX送信（印刷・PDF保存までで、そこから先に仕入先へ送る手段はアプリの外です）
- 出荷予定（受注予定）の管理
- 操作の取り消し（アンドゥ）、変更履歴の巻き戻し
- 在庫の引当（受注に対する取り置き）
- 需要予測（季節変動・トレンドの予測。在庫分析の発注点提案は過去の出庫ペースの平均のみを使います）
- 印刷用レイアウト（発注書を除く。それ以外の画面はCSVに出して表計算ソフトで印刷する想定です）
