# 入出庫帳票タブ

在庫が動いた記録をすべて残し、検索・確認するための**見るだけの画面**です。編集・削除はできません。

「なぜ在庫がこの数になっているのか」を後から追跡するための画面で、
在庫が変わる操作はすべて自動的にここへ記録されます（手入力の必要はありません）。

記録が1件もないときは「入出庫の記録がありません。ロット追加や在庫数の調整を行うと記録されます。」と表示されます。

---

## 1. 画面の構成

```
[商品名・SKU・ロットNoで検索...] [ 日付 〜 日付 ] [全区分▼] [全倉庫▼] [条件クリア]

12件 / 全40件    入庫 +120   出庫 -35   移動 10   [CSVエクスポート（入出庫帳票）]

 日時              区分      商品名  SKU     ロットNo   数量  倉庫                  備考
 2026/07/01 10:22  売上出庫  牛乳    ML-001  20260703   -10   販売倉庫              FEFO出庫
 2026/07/01 09:15  移動      チーズ  CS-001  20260615     5   販売倉庫 → 不良倉庫   倉庫移動
 2026/06/30 18:40  入荷      牛乳    ML-001  20260707   +10   販売倉庫              ロット追加
```

**新しい記録が上**に並びます。

---

## 2. 記録される区分

| 区分 | 方向 | 主にどんなときに記録されるか |
|------|------|------------------------------|
| 入荷 | 入庫（+） | ロットを新規追加したとき、ロット行の「入庫」で区分「入荷」を選んだとき |
| 調整入庫 | 入庫（+） | ロット行の「入庫（調整入庫）」、ロット編集で数量を増やしたとき、Excelインポートで増えたとき、棚卸で増えたとき |
| 売上出庫 | 出庫（−） | 通常の出荷。ロット行の「出庫」、FEFO出庫の既定区分 |
| 調整出庫 | 出庫（−） | 数量調整のほか、**ロット削除・商品削除**で在庫が消えたとき、Excelインポート・棚卸で減ったとき |
| 廃棄 | 出庫（−） | 期限切れなどの処分。ロット行の「出庫」やFEFO出庫で選択 |
| 移動 | 移動 | 倉庫間の移動。ロット編集で倉庫を変えたときも記録されます |

- 数量は、入庫が `+`、出庫が `−`、移動は符号なしで表示されます。
- 移動は**倉庫をまたぐだけ**なので、全体の在庫総数は変わりません（1件で `移動元 → 移動先` を表します）。

「どの操作が、どの区分・備考で記録されるか」の完全な一覧は
[data-and-rules.md](data-and-rules.md#在庫が動く操作と帳票の対応) を参照してください。

> **1つのロットの動きだけを追いたいときは[ロット追跡タブ](trace.md)が便利です。**
> この画面でロットNoを検索して目視で追う代わりに、入荷→移動→出庫を時系列に並べ、
> 残っている数量と既に出た数量の内訳をまとめて表示します。

---

## 3. 表の各列

| 列 | 内容 |
|----|------|
| 日時 | 記録された日時（お使いの端末のローカル時刻） |
| 区分 | 上表の6種類。入庫・出庫・移動で色分けされます |
| 商品名 / SKU | **記録した時点の**商品名・SKU。あとで商品名を変えても過去の記録は変わりません |
| ロットNo | 対象ロットの番号 |
| 数量 | 動いた数量（符号つき） |
| 倉庫 | 移動なら `移動元 → 移動先`、入庫なら入った倉庫、出庫なら出た倉庫 |
| 備考 | どの操作から記録されたかの手がかり（`ロット追加` `FEFO出庫` `棚卸` `Excelインポート` `商品削除` など）。ロット行の入庫・出庫からの記録は空欄です |

---

## 4. 絞り込み

| 条件 | 動作 |
|------|------|
| 検索欄 | 商品名・SKU・ロットNoの部分一致 |
| 日付範囲 | 開始日・終了日（**どちらもその日を含む**）。片方だけの指定も可能 |
| 区分 | 6区分から1つ選択 |
| 倉庫 | **移動元・移動先のどちらかが一致**すればヒット（倉庫をまたぐ移動は、両方の倉庫の絞り込みに出ます） |
| 条件クリア | すべての条件を解除（何か絞り込んでいるときだけ表示） |

条件は同時に効きます。合致する記録がないときは「条件に一致する記録がありません。」と表示されます。

---

## 5. 集計とCSV

表の上の集計は、**絞り込み後の表示中の記録**に対する合計です。

| 表示 | 意味 |
|------|------|
| N件 / 全M件 | 表示件数 / 全件数（絞り込み中のみ「/ 全M件」が付きます） |
| 入庫 +N | 入荷・調整入庫の数量合計 |
| 出庫 -N | 売上出庫・調整出庫・廃棄の数量合計 |
| 移動 N | 移動の数量合計 |

「CSVエクスポート（入出庫帳票）」は、**いま絞り込んで表示している記録だけ**を `入出庫帳票_YYYY-MM-DD.csv` に出力します。
月次の集計は、日付範囲で絞ってからCSVに出す想定です。

```
日時,区分,商品名,SKU,ロットNo,数量,移動元倉庫,移動先倉庫,備考
2026/07/01 10:22,売上出庫,牛乳,ML-001,20260703,-10,販売倉庫,,FEFO出庫
2026/07/01 09:15,移動,チーズ,CS-001,20260615,5,販売倉庫,不良倉庫,倉庫移動
```

---

## 6. 注意点

- **誰が操作したかは記録されません**（ログイン機能がないため）。
- 帳票の記録は編集・削除できません。誤った操作をした場合は、打ち消す操作（逆方向の調整入庫・調整出庫）を行い、
  両方の記録を残す運用になります。
- **古いデータの扱い**：旧バージョンで記録された「入庫」「出庫」という区分は、読み込み時に自動で新しい区分に変換されます
  （倉庫移動の出庫＋入庫の2件は「移動」1件に統合、ロット追加による入庫は「入荷」、それ以外は調整入庫／調整出庫）。
  倉庫を記録していなかった時期の記録は倉庫列が空欄になり、倉庫での絞り込みにはヒットしません。
- ヘッダーの「リセット」を押すと、帳票もすべて消えます。

### 開発者向けメモ

- 画面：`src/LedgerView.tsx`（絞り込み条件はローカル状態、計算は純粋関数）
- 計算：`src/useInventory.ts` の `filterLedger` / `ledgerTotals` / `ledgerCsv` / `exportLedgerCsv` / `transactionDirection`
- 記録の追加：`addTransaction` / `addTransactions`（棚卸のような一括記録は後者で1回の保存にまとめる）
- 日付の絞り込みは表示と食い違わないよう `localDateKey` でローカル日付に直してから比較している
