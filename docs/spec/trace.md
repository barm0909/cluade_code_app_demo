# ロット追跡タブ

「このロットが、いつ入って、どこを経由して、いつ出たか」を1画面で確認するための**見るだけの画面**です。
入出庫帳票に残っている記録を、ロット単位で時系列に並べ直して見せます。

回収（リコール）や品質のお問い合わせがあったときに、
「そのロットをどれだけ仕入れ、いくつ出荷し、いま何個残っているか」をすぐ答えるための画面です。

この画面で在庫が動くことはありません。何を押しても記録は増えません。

---

## 1. 画面の構成

この画面は2段階です。**追跡したいロットを選ぶ** → **そのロットの履歴を見る**。

### 1-1. ロットを選ぶ

```
[ロットNo・商品名・SKUで検索...]

6件   追跡したいロットの「追跡」を押すと、入荷から出庫までの履歴を時系列で表示します。

 商品名  SKU     ロットNo  賞味期限  現在庫    記録件数  最終記録           操作
 牛乳    ML-001  20260818  3日後          4          3  2026/08/15 12:55   [追跡]
 チーズ  CS-001  20260813  期限切れ       2          0  —                  [追跡]
 食パン  BR-001  20260810  期限切れ  在庫なし        5  2026/08/11 09:12   [追跡]
```

| 列 | 内容 |
|----|------|
| 商品名 / SKU / ロットNo | 追跡対象のロット |
| 賞味期限 | 在庫が残っている場合のみ表示されます |
| 現在庫 | いま残っている数。**出しきったロットは「在庫なし」**と表示されます |
| 記録件数 | 入出庫帳票に残っている件数。0件なら追跡できる履歴がありません |
| 最終記録 | 最後に動いた日時 |

- **在庫が残っていないロットも一覧に出ます。** 回収の連絡は在庫を出しきった後に来ることが多く、
  現在庫のあるロットだけでは肝心のロットを追えないためです。
- 並び順は「最後に動いた日時の新しい順」です。一度も動いていないロットは最後に並びます。
- 検索欄は**ロットNo・商品名・SKU**の部分一致です。商品名で検索すれば、その商品のロットが並びます。

> **同じロットNoでも商品が違えば別の行になります。**
> ロットNoは賞味期限から作るため（例：2026年7月1日 → `20260701`）、
> 期限が同じなら別商品でも同じ番号になります。追跡は必ず「商品＋ロットNo」の組で行います。

### 1-2. 履歴を見る

```
[← ロットの選択に戻る]  牛乳 ML-001  ロット 20260818     [CSVエクスポート（ロット追跡）]

 入庫合計   出庫合計（既に出た数量）  帳票上の残数  現在庫    記録件数
   +24              -6                   18          18         4
  入荷 24    売上出庫 4 / 廃棄 2       入庫 − 出庫   販売倉庫   移動 1件

 現在の在庫   経路: 販売倉庫 → 保留倉庫
  倉庫        賞味期限   在庫数
  🟢販売倉庫   3日後        18

 履歴（古い順）  2026/08/10 09:00 〜 2026/08/15 12:55
 ● 入荷      2026/08/10 09:00  +24            残 24
   🟢販売倉庫   入荷予定（山田乳業）

 ● 売上出庫  2026/08/15 12:55  -4             残 20

```

## 2. 上段のサマリ

| 項目 | 意味 |
|------|------|
| 入庫合計 | このロットに入ってきた数量の合計（入荷・調整入庫）。下段は区分ごとの内訳 |
| 出庫合計（既に出た数量） | このロットから出ていった数量の合計（売上出庫・調整出庫・廃棄）。下段は区分ごとの内訳 |
| 帳票上の残数 | 入庫合計 − 出庫合計。**帳票の記録から計算した残り** |
| 現在庫 | 実際にいま在庫として残っている数。下段は保管倉庫 |
| 記録件数 | 入出庫帳票に残っている件数と、そのうち移動の件数 |

「既に出た数量の内訳」は出庫合計カードの下段に出ます（例：`売上出庫 4 / 廃棄 2`）。
**売れて出たのか、捨てて出たのか**が分かるので、回収時の連絡先の判断に使えます。

## 3. 現在の在庫

いまこのロットが**どの倉庫に何個あるか**の一覧です。

- 倉庫間の一部移動をすると、同じロットNoの在庫が複数の倉庫に分かれます。その場合は倉庫ごとに行が並びます。
- 出しきった・廃棄した・ロットを削除した場合は「このロットの在庫は残っていません」と表示されます。
- 「経路」は、帳票に出てくる倉庫を**出てきた順**に並べたものです（例：`販売倉庫 → 保留倉庫`）。

## 4. 履歴カード

入出庫帳票のうち、このロットの記録だけを**古い順**（入荷 → 移動 → 出庫）に並べたものです。
入出庫帳票タブが新しい順なのと逆なのは、「入ってから出るまで」を上から順に読むためです。

| 表示 | 内容 |
|------|------|
| 区分バッジ | 入荷 / 調整入庫 / 売上出庫 / 調整出庫 / 廃棄 / 移動（帳票と同じ区分・同じ色分け） |
| 日時 | 記録された日時 |
| 数量 | 入庫は `+`、出庫は `−`、移動は符号なし |
| 残 N | **その記録の直後**のロット残数。移動では増減しません（倉庫が変わるだけのため） |
| 倉庫 | 移動は `移動元 → 移動先`、入庫は入った倉庫、出庫は出た倉庫 |
| 備考 | `ロット追加` `FEFO出庫` `棚卸` `一括廃棄` など、どの操作から記録されたかの手がかり |

## 5. CSVエクスポート

「CSVエクスポート（ロット追跡）」で、**いま表示しているロットの履歴**を `ロット追跡_YYYY-MM-DD.csv` に出力します。
残数の推移も列に入っているので、回収報告の資料にそのまま添えられます。

```
日時,区分,商品名,SKU,ロットNo,数量,移動元倉庫,移動先倉庫,残数,備考
2026/08/10 09:00,入荷,牛乳,ML-001,20260818,24,,販売倉庫,24,入荷予定（山田乳業）
2026/08/12 14:20,移動,牛乳,ML-001,20260818,5,販売倉庫,保留倉庫,24,倉庫移動
2026/08/15 12:55,売上出庫,牛乳,ML-001,20260818,-4,保留倉庫,,20,FEFO出庫
```

## 6. 数字が合わないときの見方

「帳票上の残数」と「現在庫」は原則として一致します。一致しないときは画面に注意書きが出ます。

| 表示 | 意味 | どうすればよいか |
|------|------|------------------|
| 「入出庫の記録がありません。」 | このロットは帳票を記録し始める前からある在庫です（サンプルデータやリセット直後の初期在庫） | 異常ではありません。追跡できるのは記録が付いて以降の動きだけです |
| 「帳票上の残数と現在庫が一致しません。」 | 記録前からあった在庫が混ざっている、または帳票を記録しない経路で在庫が変わった | 帳票の記録開始前の在庫がないか確認してください。運用開始後のロットで出る場合は在庫の実数を棚卸で合わせてください |

- **誰が操作したかは記録されません**（ログイン機能がないため）。
- 商品マスタから削除された商品のロットも、帳票の記録が残っていれば追跡できます
  （その場合、商品名は削除時点の名前で表示されます）。
- ヘッダーの「リセット」を押すと帳票も消えるため、追跡できる履歴もなくなります。

---

## 7. 使い方の例（回収の連絡が来たとき）

1. 仕入先から「ロット `20260818` に不具合」と連絡が来る。
2. ロット追跡タブで `20260818` を検索し、対象の商品の「追跡」を押す。
3. **出庫合計の内訳**を見る → 売上出庫が何個あるか（＝出荷先へ連絡が必要な数量）。
4. **現在の在庫**を見る → いくつ、どの倉庫に残っているか（＝回収・保留する分）。
5. 「CSVエクスポート（ロット追跡）」で履歴を書き出し、報告資料にする。
6. 残っている在庫は、在庫一覧タブまたはダッシュボードから保留倉庫へ移動・廃棄する。
