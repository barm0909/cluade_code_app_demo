# FEFO出庫機能

商品と数量だけを指定すると、**賞味期限の近いロットから順に自動で引き当てて出庫する**機能です。
FEFO = First Expired, First Out（先に期限が来るものから先に出す）。

従来の出庫はロット行の「出庫」ボタンから1ロットずつ数量を減らす操作だけで、
「どのロットから出すか」の判断と、複数ロットにまたがる場合の按分が現場任せでした。
FEFO出庫はその判断を自動化し、期限の古い在庫が倉庫に残り続けるのを防ぎます。

専用のデータは持たないため、DBマイグレーションや Worker API の追加は不要です。

---

## 画面

在庫一覧タブの**商品行**の操作列に「FEFO出庫」ボタンが追加されます
（ロット行の「入庫 / 出庫」は従来どおりロット単位の操作として残ります）。
合計在庫が0の商品ではボタンは無効です。

モーダルの入力項目:

| 項目 | 内容 |
|------|------|
| 倉庫 | 既定は「全倉庫」。指定するとその倉庫のロットだけが引当対象 |
| 出庫区分 | `売上出庫` / `調整出庫` / `廃棄`（`OUTBOUND_TYPES`）。既定は `売上出庫` |
| 出庫数量 | 引き当てたい数量 |
| 期限切れロットも引当対象にする | 既定オフ。オンにすると期限切れロットを最優先で引き当てる |

入力に応じて**引当プレビュー**（ロットNo / 賞味期限 / 倉庫 / 引当数 / 引当後の残数）が
即座に更新されます。プレビューは実際の出庫とまったく同じ `planFefoShipment` の結果なので、
確定後に別のロットから引かれることはありません。

在庫が足りない場合は「在庫が N 不足しています」と表示し、出庫ボタンを無効にします
（数量を減らすか、対象倉庫を見直してもらう）。
期限切れを除外した結果として引当できなかった在庫がある場合は、その数量も注記します。

確定すると、引き当てたロットと数量をアプリ内ダイアログで通知します。

---

## 引当ルール

`fefoLotOrder` が引当対象のロットを次の順に並べます。

1. 在庫数が0のロットは対象外
2. 倉庫を指定した場合、その倉庫以外のロットは対象外
3. 期限切れロット（`daysUntilExpiry < 0`）は既定で対象外。
   食品では期限切れは出荷ではなく廃棄が原則のため。
   `includeExpired` を指定した場合のみ対象に含め、期限が最も古いので先頭に並ぶ
4. 賞味期限の**昇順**。賞味期限のないロット（ラベル等の非食品）は最後
5. 同じ賞味期限ならロットNo→id 順（結果を安定させるため）

この順に「そのロットの在庫数」と「残りの出庫数量」の小さいほうを引き当て、
出庫数量を満たすか対象ロットが尽きるまで繰り返します。
足りなかった分は `shortage` として返り、**引ける分だけは出庫されます**
（画面では `shortage > 0` の状態では確定できないようにしていますが、
`shipFefo` 自体は部分出庫を許容します）。

## 帳票への記録

引き当てたロット1件につき1件の出庫トランザクションを記録します
（`type` は選択した出庫区分、`note` は `FEFO出庫`、`fromWarehouseId` はそのロットの倉庫）。
まとめて1件にはせず、どのロットから何個出したかが入出庫帳票に残るようにしています。
複数件は `addTransactions` で1回の state 更新・1回の PUT にまとめます。

```
2026/08/13 06:53  売上出庫  牛乳  ML-001  20260816  -10  販売倉庫  FEFO出庫
2026/08/13 06:53  売上出庫  牛乳  ML-001  20260820   -2  販売倉庫  FEFO出庫
```

## 実装

引当計算は `src/useInventory.ts` の純粋関数で、`src/ShipFefoModal.tsx` は表示と入力のみを担当します
（`LedgerView` / `StocktakeView` / `DashboardView` と同じ構成）。

| 関数 | 役割 |
|------|------|
| `planFefoShipment(product, quantity, options?)` | 引当計画（`allocations` / `allocated` / `shortage` / `skippedExpired`）を返す。状態は変更しない |
| `fefoLotOrder(product, options?)` | 引当対象のロットを FEFO 順に並べて返す |
| `shipFefo(productId, quantity, options?)` | フックのミューテーター。計画どおりに在庫を引き落とし、帳票へ記録し、計画を返す |

`options` は `{ warehouseId?, includeExpired? }`（`FefoOptions`）で、
`shipFefo` はさらに `{ type?, note? }` を受け付けます。`type` は出庫区分だけを許す
`OutboundTransactionType`（`売上出庫` / `調整出庫` / `廃棄`）です。

テストは純粋関数とミューテーターが `src/test/fefo.test.ts`、モーダルが
`src/test/ShipFefoModal.test.tsx` です。期限まわりのテストは `daysUntilExpiry` が
実時刻を参照するため、固定日付ではなく「今日からN日後」で組み立てています。
